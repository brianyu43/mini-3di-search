# mini-3di-search 시작 패키지

**이 패키지는 연구 계획과 Codex 프롬프트다. 구현 코드·검증된 벤치마크 결과는 아직 포함하지 않는다.**

Foldseek에서 영감을 받아 3Di 검색 단계를 직접 구현한다. 공식 도구는 구조 표현 추출과 외부 비교군에만 쓰고, 자체 인덱스·후보 필터·정렬·평가는 직접 작성하도록 설계했다.

## 파일

| 파일 | 역할 |
|---|---|
| [RESEARCH_PLAN.md](RESEARCH_PLAN.md) | 연구 성격, 선택 이유, 구현 경계, 알고리즘 계약, 데이터·평가·일정 |
| [CODEX_PROMPTS.md](CODEX_PROMPTS.md) | 첫 구현, 단계별 후속 작업, 독립 검토에 사용할 프롬프트 |
| [AGENTS.md](AGENTS.md) | 저장소 공통 정확성·실험·자원·작업 범위 규칙 |
| [SOURCES.md](SOURCES.md) | 원논문·공식 저장소·데이터·개발 문서 |

## 시작

이 파일들을 **새 빈 프로젝트 폴더**에 둔다. 기존 연구 저장소의 AGENTS.md나 README를 덮어쓰지 않는다.

Codex에서 그 폴더를 작업 대상으로 열고 아래 문장을 전달한다.

```text
AGENTS.md, RESEARCH_PLAN.md, SOURCES.md를 읽어라.
CODEX_PROMPTS.md의 “1. 첫 세션: M0 + M1만 구현” 블록을 이번 작업 지시로 사용해라.
M0/M1의 코드와 테스트를 실제로 구현·실행하고, 결과를 기록한 뒤 멈춰라.
M2 이후나 실제 구조 DB 다운로드는 자동으로 진행하지 마라.
```

첫 세션의 목표는 네트워크·Foldseek 없이도 작동하는 작은 synthetic 검색기와 독립 oracle 검증이다. 그 다음 인덱스·필터, 실제 구조 데이터, 공식 비교, Numba 최적화, 동결 평가 순서로 진행한다.

기본 예산은 40–60시간, 약 4주다. 첫 프로젝트에서 GPU·거대 데이터·웹 UI를 함께 만들지 않는다.

## 공개 포트폴리오에서의 표현

완료 후에는 “Foldseek 전체를 재현했다”가 아니라 “upstream 3Di encoder를 사용하고 검색 단계를 교육용으로 재구현·평가했다”고 설명한다. 원본 실행 재현, 직접 작성한 코드, 생략한 알고리즘, AI 보조 범위를 구분한다.
